# Initial unusual effect previews

Implemented 2026-10-07. The installed hat/taunt catalog is selectable through native Source simulation. Silver Serenade and Arctic Delight remain the visually approved references. Weapon effects and playback transport changes are deferred.

## Catalog rollout

The picker indexes original PCF element directories to locate each schema system. All 645 installed systems in the current 646-system catalog passed a three-second native smoke run; `stamp_spin` is missing from installed definitions and remains disabled. This checks simulation and bridge validity, not visual parity for every effect. Selections persist as schema IDs in scenes/session state and copy with the character; old Silver/Arctic boolean settings still load.

New effects run Valve's built-in operators with posed model hitboxes, hitbox-relative coordinates and Source random sampling. Hat attachments/root-bone fallback and taunt refire intervals come from the schema. Team-colored systems follow the character's team. The helper mounts TF2 and inherited HL2 assets, exports previous positions/trail lengths/timestep, and supports large child graphs (Demigodery has 427 collections). Non-finite birth-tick render attributes are omitted from exported geometry without changing native state.

WebGL draws sprite cards, sprite trails, screen-velocity-oriented sprites and ropes. Cards support view yaw, material orientation, frame blending and overbright factors. World traces/lighting, exact mesh-inside tests, dual-sequence/channel shader features, depth feathering and some trail/screen-velocity renderer details remain compatibility approximations. Repeated taunts use Source emitter restart at the authored interval; unlike the game, this reuses the collection instead of creating a second overlapping collection. Arctic's approved compatibility backend is preserved. Failed definitions/helpers/materials produce visible errors; unsupported web operators are never silently skipped.

## Native Silver Serenade follow-up

Silver Serenade now prefers Valve's native SDK simulation when the locally built helper is available. All 36 collection instances, including the five ropes, run their built-in operators and export render attributes. The panel labels native simulation or compatibility preview. Arctic Delight still uses the web simulation because its model/hitbox queries have not been connected to the helper. See [build, protocol and remaining limits](../native/particle-probe/README.md).

The helper runs in a hidden child process per actor with bounded requests, timeouts, disposal and reload cleanup. Native motion is verified for 12 seconds, repeatable restart, moving attachment updates and separate actor runtimes. Live preview was checked on Scout with Troublemaker's Tossle Cap. Three.js still renders the result; exact visual parity has not been established. Native binaries and Valve assets remain outside Git, and release packaging is not configured.

## Using the preview

In the Viewer, select a character and open **Particles** in the bottom center panel. Hat and taunt pickers read all entries from the installed game's `cosmetic_unusual_effects` / `taunt_unusual_effects` schema categories, with English localization, IDs and name/ID/system filtering. Entries without installed definitions are explicitly disabled. **Restart effects** clears and replays the selected effects. Particles keep moving while character animation is paused. Settings belong to each character, persist in scene/session JSON, and copy with Ctrl+Add; simulation time is not saved.

Hat effects use the first equipped hat/whole-head cosmetic's authored schema attachment on its actual bonemerged skeleton, including cosmetic-only/jiggle bones. If the attachment is absent, use the cosmetic's `unusual` attachment, then its `bip_head` / `prp_helmet` / `prp_hat` bone. Only models without any head anchor fall back to the merged root when requested by the schema. With no wearable, the preview sits above the current head position with a Source Z-up offset. Removing the hat falls back to the head; equipping a hat after enabling the effect picks its attachment. Selecting other characters does not transfer effects. Arctic Delight samples the character's current hitboxes and bones, including while posed.

This attachment fallback is an explicit preview compatibility policy, rather than a literal copy of the SDK's `PATTACH_ROOTBONE_FOLLOW` path. The installed Damage Dealer model retains a seven-bone chain beginning with `bip_pelvis`, with `unusual` attached to `bip_head`. Bubbling #34 has no schema attachment and Burning Flames #13 names `muzzle`, absent on that hat. Blindly following the first merged bone puts both effects at the pelvis. The head bone search follows the names recognized by `particle_property.cpp`'s `particle_effect_use_head_origin` override; the viewer does not receive live inventory adjustment attributes. A regression reads the installed hat MDL and checks both legacy schemas, while retaining explicit attachment priority and animated transforms. No particle offsets or simulation operators were tuned per effect.

## Assets and implementation

Searing Stove #360/#361 includes rendered flame-driver children using inherited HL2 `vgui/white`. This is an intentionally untextured UnlitGeneric material. Source's DX9 generic shader binds its standard white texture when neither a base texture nor an envmap is defined. The particle loader now uses an opaque 1×1 white texture for that case instead of rejecting the entire effect graph. Authored textures that fail to load, malformed materials and unsupported untextured shaders still report errors. Regressions cover both installed Stove roots and the original inherited material.

Sulfuric Acid's missing ground splashes were a simulation dependency failure: `utaunt_waste_acid_splash` uses **Lifetime From Sequence**, but the headless Source material system did not expose the VTF sheet resource. The child existed but emitted no surviving particles. The helper now enables client sheet loading, reads resource `0x10` from original mounted VTF assets through a texture adapter, and lets Valve's `FindOrLoadSheet` parse/cache it. It creates the reachable graph to precache materials, then recreates it with the same seed before any simulation tick so every child receives the cached sheet. Resources are read once per distinct texture at startup; no assets are copied into the application and no per-effect lifetime is substituted. This applies to all native effects that depend on sheet metadata. An installed-asset regression verifies continuous splash emission, all four variants, the authored 14/30-second lifetime and ground-level positions. Catalog smoke checks still establish runtime validity rather than visual completeness for every effect.

Sulfuric Acid (#3234, `utaunt_waste_yellow_parent`) requires soft-particle fading and emissive blending in addition to ordinary depth testing. SpriteCard defaults `$depthblend` on in the SDK (`DEFAULT_PARTICLE_FEATHERING_ENABLED=1`), with `$depthblendscale=50`; the effect's additive smoke omits these keys and previously received no fading. The preview now captures opaque scene depth with particles hidden, preserving the model materials' skinning, cutouts and hidden-region behavior. Cards reconstruct view depth and fade against nearby surfaces using the material's depth scale. This independent target avoids framebuffer feedback; it is rendered only when an active effect needs soft depth, resized to the current viewport/export dimensions and disposed with the viewer. Both viewport and image exports use it. The extra pass has a rendering cost. This is a linear-depth adaptation of Source depth feathering, not a byte-identical reproduction of its DX9 compressed destination-alpha depth representation and far-depth fallback.

The spark material `particle/flamethrowerfire/flamethrowerfire102.vmt` declares `srgb?$overbrightfactor=5`, `$addself=0.5`, and soft depth scale 100. The preview resolves sRGB conditional parameters and implements the SDK SpriteCard ADDSELF formula with premultiplied blending; other materials without ADDSELF preserve equivalent normal/additive blending. These changes retain authored brightness instead of effect-specific multipliers. Installed-asset regression checks verify smoke defaults, explicit depth disable, spark brightness/self-emission, depth uniforms and export-camera projection handling. A live Sulfuric Acid preview rendered successfully after the changes; matching the game's lighting/bloom and remaining material features still requires visual comparison.

The Radioactive/Gamma Rays floor wash also revealed an orientation precedence bug: the VMT loader's default `$orientation=0` overrode the PCF floor renderer's `orientation_type=2`, turning its 100-unit horizontal glow into a camera-facing card across the character's legs. Source's `C_OP_RenderSprites::Render` explicitly sets the material's `$orientation` from the renderer before binding; the preview now does the same. The orientation-2 shader branch uses Source XY (the ground plane), while orientation 1 remains Z-aligned. Installed regressions cover all four radioactive floor variants plus the upright mode. Camera depth bias remains a separate setting.

Gamma Rays (#3239/3240) and Radioactive (#3242) author `Visibility Camera Depth Bias = -7` on their main smoke and ring renderers, while those two VMTs explicitly set `$depthblend 0`. Source initializes this bias even when the visibility-proxy control point is disabled, and `C_OP_RenderSprites::RenderSpriteCard` offsets each rendered center toward the camera by the signed bias. The preview now applies the same eye-ray offset before existing depth testing, so negative bias pushes these cards behind nearby character geometry. Native particle positions remain unchanged. Installed-asset regressions cover RED/BLU, green and purple variants, positive/negative/zero offsets and degenerate camera positions. This implements camera depth bias; it does not yet implement soft-particle depth feathering or visibility-proxy queries.

Shroud of Darkness (#3235) exposed two shared renderer omissions. Its crow sheet has 63 frames with a total duration of 63 sheet units, and `animation rate` ~0.5 with FPS mode disabled. Source's `C_OP_RenderSprites::Render` scales the rate by 1024 samples per cycle; `RenderSpriteCard` divides by the sheet duration only in FPS mode. The preview now converts normalized cycles into sheet units, so the crow completes a wing cycle in about two seconds rather than advancing one frame every two seconds. FPS mode advances sheet units directly; lifetime-fit mode retains its normalized lifetime timing. The crow VMT disables frame blending, which remains respected.

`render_screen_velocity_rotate` is a roll modifier, not a geometry renderer: the official SDK library's `C_OP_RenderScreenVelocityRotate::Render` writes `atan2(view delta Y, view delta X) + forward_angle` into ROTATION. The preview applies it to drawing renderers even when it is the second renderer entry, using the current camera/model transform and native PREV_XYZ. Shroud's authored -90 degree offset is retained. Multiple drawing renderers now each receive their own settings; modifiers do not produce duplicate cards. Installed-asset regression tests verify changing crow atlas frames, the authored angle, camera-relative rotation, and disabled frame blending. Live-game visual parity still needs user comparison.

## Fidelity and limits

### Converter audit (2026-10-11)

A catalogue-wide pass (all 646 effects, 760 particle materials) found these pipeline gaps, now fixed:

- **Legacy `Sprite` materials use vertex colour and alpha.** The SDK's `sprite_dx9.cpp` defaults `IGNOREVERTEXCOLORS` to 1, which would leave additive beams white, but the game tints them with the particle colour (the chains of Cursed Confinement are purple). Vertex colour/alpha are used unless a material sets `$ignorevertexcolors 1`. Texture reads stay raw (`NOSRGB` default).
- **`Refract` materials** (23 materials, 25 effects, among them Deep Dive) had no base texture, which rejected the whole effect. They are drawn as in `refract_ps2x.fxc`: the picture behind the particle is read at its pixel moved by `normal.xy * normal.a * $refractamount * particle alpha`, times `$refracttint` and the particle colour, with alpha = particle alpha * normal alpha. The normal map is the material's texture (and its sheet). The opaque-scene pass that already fed soft particles keeps its colours (half float) when a refract draw has particles.
- **Particles live in the world.** The control points and hitboxes of native unusual effects are put in world space and the group is drawn world-fixed (as for weapon effects), so a character that walks, or is dragged, leaves what it emitted behind (the lingering steps of Electrocution). The compatibility backend (Arctic) stays in character space.
- **The world has a floor.** The helper's trace query used to report "no hit" for every ray, so a particle that relies on **Collision via traces** to stop at the ground never did. The footprints of Electrocution (a parent that falls under 500000 gravity, with children left where it lands) fell to z = -250000 and were never seen. The viewer now sends its floor height with every step and the helper's traces hit that plane (normal up). A regression checks that the footprint particles rest at the floor with it and are lost without it.
- **Frames travel as bytes.** The helper wrote every particle as text, Rust parsed it and wrote it as JSON again and the page parsed that: 15 ms of a 25 ms step of Electric Impulse at its burst (2,700 particles, 430 KB). A step now asks for a binary frame (float32 per attribute), Rust only checks it (counts, finite numbers, whole sprite sequences) and hands the bytes to the page: 2 ms, 180 KB. The first frame of a helper stays text (it names the collections).
- **Particles are drawn by the clock of the view.** A state of the helper arrives some milliseconds after the tick it describes and ticks are 60 Hz at any display rate, so particles moved by one tick at a time, irregularly (0, 1 or 2 ticks in a frame). Draws now move every particle on by its own last step for as long as its state is behind the clock (at most three ticks; not for a step of thousands of units a second, which is a placement), and the next step is sent the moment the reply arrives.
- **Crowds.** Measured with 12 effects started at once: each helper has a lock of its own (the pool is only locked to find or add one), where a single lock made every effect in the scene stop for the 100 ms or more that any new one took to start (the worst frame of the others went from 114 ms to 8 ms). A system with no particles is not visible to the renderer (761 empty draws of six Electric Impulses cost 1 to 2 ms of submission a frame). A helper is about 36 MB and at most 32 run at once; condition lanes are limited to 5 per system. Blood (100 decals), stuck arrows (48) and gib pieces (400, oldest characters first; the character stays gone) are capped.
- **Tiny textures** (`vgui/white`, no resource section) have no sheet instead of being an error.
- **Cost:** an idle draw does no work and a busy one uploads only the used part of its buffers (a 141-draw effect like Electric Impulse re-uploaded every buffer, full size, every frame).

`C_OP_RenderSpritesTrail` was checked against the SDK's `particles.lib` disassembly: length = |PREV_XYZ - XYZ| / dt * TRAIL_LENGTH * fade, clamped to [min, max], width = min(radius, length), drawn backwards from the particle. Ours matches, including the minimum length for any particle that moved at all.

Thundering Spirit (#3066, `utaunt_elebound_purple_parent`) uses twelve rope instances with `effects/electro_beam`, a legacy `Sprite` material. `materialsystem/stdshaders/sprite_dx9.cpp` defaults `NOSRGB` and `IGNOREVERTEXCOLORS` to 1; the latter bypasses vertex tint and alpha in the additive mode. Asset loading and both particle draw paths honor these defaults and explicit overrides. Legacy Sprite uses `HDRCOLORSCALE`, not SpriteCard's `OVERBRIGHTFACTOR`. Applying SpriteCard-style texture decoding and vertex modulation to electro_beam darkened portions of the visible arc. Installed-asset coverage checks both trail definitions and material defaults.

Rope texture scrolling uses Source distance units: `(distance + collectionTime * texture_scroll_rate) / (texel_size * materialMappingHeight)`. The SDK `particles.lib` implementations of `C_OP_RenderRope::InitializeContextData` and `RenderUnsorted` establish the shared scale; `public/materialsystem/imaterial.h` identifies the mapping-height call. Infernal Wraith (#195), Phantom Crown (#196), and Ancient Specter (#197) use a 256-pixel spirit texture, texel size 0.06, and scroll speed 25, giving about 1.63 repeats per second. Treating 25 as repeats per second caused rapid, aliased playback. Installed-asset regression coverage checks all three graphs, per-tick UV movement, and a complete 0.6144-second cycle.

Arctic movement now follows the SDK library's 30 Hz drag reference and applies acceleration after damping. Scalar oscillation uses `SinEst01SIMD` from `public/mathlib/ssemath.h` and writes yaw in radians without degree conversion. Screen-facing sprites keep roll and yaw separate: yaw rotates the card about view-space Y, including depth displacement and the edge-on appearance, following `materialsystem/stdshaders/spritecard_vsxx.fxc`. This corrects specific mismatches; it does not establish full renderer parity.

The compatibility backend uses original PCFs, child graphs, parameters and textures, but random sampling, movement integration, oscillation/fade details and particle shader lighting are approximations. Native Silver replaces simulation with Valve's built-in operators. Both still use WebGL rendering: smooth joined ribbons, discrete sheet frames, and limited sprite orientation support. Sheet interpolation, multiple image channels, environmental lighting/visibility and exact renderer parity remain unverified. Ribbon `subdivision_count` now means intervals per particle pair, matching the native operator, rather than an extra interval.

Both effects were visually confirmed in the running Windows app on Soldier: Silver's musical staff and notes above the head, Arctic's purple glow and drifting sparkles around the body. Scene/session restoration after live reload was also observed. Exact game fidelity, every class/hat/style combination, and multi-character performance have not been benchmarked. Do not assume other effects work merely because their PCFs parse; expand support by inventorying and testing their complete graphs.

# Transparent screenshot and shadow handling (2026-10-08)

Additive sprites/trails/ropes preserve destination alpha with separate RGB/alpha blend factors. Adding texture alpha made black additive cards opaque in PNGs even though the viewport only showed their emitted light. Normal particle alpha blending is unchanged. Particle draw materials explicitly opt out of the custom ground-shadow silhouette pass, which otherwise replaces their shaders and projects whole sprite cards as solid geometry.

Transparent captures retain display-space colour over black, including emission at zero alpha. After GPU readback, `resolveCaptureEmission` chooses alpha large enough to represent the light and unpremultiplies RGB for ordinary PNG compositing. This prevents opaque black borders, handles emission overlapping soft ground-shadow coverage, and keeps black shadow opacity. Standard PNG cannot express true additive light over every possible background; the exported glow preserves the captured appearance over black and uses ordinary alpha on other backgrounds. Four focused regression checks cover compositing, character/shadow alpha, additive blend factors, and exclusion/restoration in the actual ground-shadow pass. Frontend build passed; full in-app visual comparison remains pending.
