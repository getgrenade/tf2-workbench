# Lighting and post-processing

The Lighting tab stores Simple and Advanced rigs inside `light.rig`. Linked lights synchronize direction, colour, intensity, name and enabled state when switching modes. Directions convert between camera-relative Simple space and Advanced world space using the current camera orientation. Lights copied from Simple mode retain their source slot: deleting one in Advanced disables its Simple slot, and enabling that slot again recreates its Advanced light when entering Advanced mode. Added scene lights remain independent, and Advanced positions and shadow settings are retained. Older scenes initialize the simple primary light from their existing settings; enabled legacy point lights migrate into Advanced mode.

Simple mode retains the HLMV-style ambient cube and Source material shaders, with three camera-relative directional lights. Only the first starts enabled. Directions use the same azimuth/elevation convention as the previous light. The shaded sphere supports pointer dragging and keyboard arrows; Ctrl + left drag in the viewport edits the selected light. These lights do not cast physical shadows.

Advanced mode supports up to eight independently named directional, point or spot lights. Point/spot positions are absolute world coordinates, editable numerically or through the existing viewport translation gizmo. Directional/spot directions are world-relative. Colour, intensity, radius/falloff and spot cone settings feed the custom Source body and eye shaders, including diffuse and specular illumination.

Ctrl-click + Add duplicates the selected Advanced light's type, position, orientation and other settings, then selects the copy. Copies have unique names and remain independent of Simple-mode slots; the eight-light limit still applies.

Both modes use a compact vertical light list beside the sphere and editing controls. Right-click a row and choose Rename to edit its name inline; Enter/blur saves and Escape cancels. Each row contains a marker/gizmo button and enabled checkbox, with deletion also available in Advanced mode. Ambient colour and intensity share one compact row above the list; the Advanced mode toggle sits at the bottom.

Click the number beside any lighting slider to type an exact value (angles are in degrees). Enter or leaving the field applies the value within its supported range; Escape cancels. UI refreshes preserve unfinished typing, and sliders and the sphere continue to update these values.

The Light setups library saves standalone versioned JSON files with ambient colour/intensity and both Simple/Advanced rigs, including spot orientation and real-shadow settings. Applying a setup replaces the entire current light rig; characters, cameras, poses and post-processing are unaffected. Viewport markers are hidden on application. Enter a name and Save (or leave the name empty for an automatic name), click a saved setup to apply it, and star entries for quick favorites. Favorites sort first and the Favorites only filter restricts the list; stars persist in each setup file across scenes and restarts. Delete removes the preset file, not lights already applied to the scene.

Presets live in `light-setups` beside the executable, following the portable pose-library convention. If that directory cannot be written, the app configuration directory's `light-setups` folder is used. Folder opens the active location; JSON files can be copied there to share setups, then Refresh reloads the list. Unsupported files are skipped and reported; saving never overwrites a listed filename. No scene data or screenshots are stored in these files.

With the row's gizmo button enabled, Advanced point/spot lights use the shared viewport gizmo toolbar. W moves the light, R edits its radius, and E rotates spot lights (the key picks the gizmo; Shift + the key edits by mouse, Alt + the key resets); X/Y/Z constrain modal transforms. Click or Enter confirms, Esc/right-click cancels, and Alt+G/R/S resets the corresponding value. Point lights have no rotation controls. Spot lights show a cone aligned with their emitted direction, cone angle and distance cutoff; point lights show a range sphere. Light helpers are excluded from screenshots, shadow maps and particle depth occlusion.

Spot rotation rings and R-axis constraints use the light's local axes, with local +Z pointing along the emitted beam. Full orientation (including roll) is saved, so local rings retain their alignment after a drag and scene reload; numeric angle edits rebuild the orientation when necessary.

Optional real shadows use a lazily allocated packed-depth atlas: one 512px tile for directional/spot lights, six cube faces for point lights. A four-tap filtered comparison attenuates that light's direct illumination on character/cosmetic surfaces. Ambient and self-illumination remain independent. Authored UV visibility masks, manually hidden triangles and alpha-test cutouts also apply in the depth pass. Transparent/additive particles and viewport helpers do not cast shadows. Static maps reuse the previous frame; animations and changed lights redraw them. Point shadows cost six scene depth renders per enabled light. The atlas is released when no enabled light needs shadows.

The Post-processing tab contains AO, the existing soft ground-shadow decal and gradient fog. That decal remains independently adjustable; it does not represent the advanced light's physical shadow map. The viewport and exported screenshots use the same light rig. Captures invalidate the cached shadow map afterward so an isolated thumbnail cannot change the next full-scene render.

Post-processing also offers an optional Fresnel rim light for character, eye and cosmetic surfaces. It adds coloured illumination at grazing viewing angles independently of the material's authored TF2 rim light. Strength controls brightness, Edge width controls the Fresnel falloff, Direction picks a side in camera coordinates (0° right, 90° top, ±180° left), and Spread controls how far the directional rim extends around the edge. All around removes the directional restriction. The effect follows the current viewport or capture camera, supports perspective and orthographic views, preserves surface transparency, and is saved with scenes/session state. It does not light particles or cast shadows and uses the existing material passes without additional render targets. It is disabled by default and older scenes restore it disabled.

Painted rim thresholds the complete Fresnel/directional mask into a solid, uniformly bright band. Line cutoff controls which part becomes the line (higher values make it thinner), while Edge softness feathers its boundary. At zero softness, a pixel-sized antialiased transition keeps the line crisp without jagged stair steps. The settings persist with the rim light; older scenes keep smooth shading.

Validation: production build; rig defaults, camera/world space, scene persistence, mode-switching and selection regressions; browser WebGL compilation/rendering of Source body/eye shaders and directional, point and spot shadows; sphere and Add/Delete controls checked in the browser.
